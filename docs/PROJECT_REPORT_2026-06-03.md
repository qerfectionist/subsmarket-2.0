# SubsMarket: отчет о проделанной работе и текущем состоянии

Дата: 2026-06-03  
Источник: история проекта, текущий код, git-история, продуктовая база по Telegram-чату.

## 1. Коротко

SubsMarket вырос из идеи Telegram Mini App для P2P-обмена подписками, тарифами и гигабайтами в систему правил для рынка, где главная боль - недоверие между людьми.

Первый вариант проекта больше напоминал маркетплейс/доску объявлений: пользователь создает клуб или объявление, другой пользователь вступает, дальше стороны сами договариваются. После анализа реальных Telegram-чатов стало понятно, что простой список предложений не закрывает главные проблемы: скам после предоплаты, удаление переписки, исключение из семьи после оплаты, скрытые комиссии, непонимание правил операторов и конфликтные сценарии.

Текущая продуктовая позиция: SubsMarket не должен хранить деньги и делать escrow, но должен жестко фиксировать статусы, действия и доказуемую историю. Платформа остается без банковского процессинга, но перестает быть хаотичной доской объявлений.

## 2. Что строим

Основные направления спроса:

1. Семейные подписки: YouTube Premium, Yandex Plus, Spotify, Netflix, Apple Music, Ivi.
2. Семейные тарифы связи: Tele2, Beeline, Activ/Kcell, где люди делят общий тариф.
3. ГБ-маркет: покупка и продажа лишних гигабайтов в конце месяца.
4. Аккаунты/доступы: Canva Pro, Google One, Microsoft 365, CapCut, AI-сервисы и похожие продукты.

Важное уточнение по продукту: "доступы" и "сделки" не одно и то же. Доступы - это отдельная категория товара. Сделки - это процесс покупки/продажи или вступления, который может происходить в разных категориях.

## 3. Боли из Telegram-чата

Самые частые проблемы, которые подтвердила база чата:

- Предоплата без защиты: человек платит, после этого продавец удаляет чат или исчезает.
- Удаление из семьи после оплаты: участник платит за месяц/год, но хост удаляет его через 1-2 недели.
- Перевод на баланс телефона или дропперам: сложно доказать, кто получил деньги.
- Несправедливое потребление в семейных тарифах: один участник может выкачать общий лимит.
- Непонимание "безлимита": у операторов есть fair-use лимиты, после которых скорость падает.
- Скрытые комиссии и срок жизни ГБ: например, у Beeline гигабайты могут жить 3 дня.
- Приватность общих AI-аккаунтов: в ChatGPT/Claude нет нормальной семейной изоляции, пользователи могут видеть историю друг друга.

## 4. Продуктовые правила, которые сформировались

Правила, которые теперь считаются базовыми:

- Нет escrow и банковского процессинга. Деньги идут напрямую между людьми.
- Платформа не принимает деньги и не становится стороной платежа.
- Оплата только после выдачи доступа, а не до.
- Хост не должен ставить наценку. Цена места считается автоматически: общая стоимость / количество участников.
- Реквизиты показываются не всем подряд, а только в правильном статусе.
- Все ключевые действия фиксируются в AuditLog.
- При споре семья замораживается, чтобы нельзя было продолжать спорные действия.
- Pending-заявка не занимает место и не считается активным участником.
- Altel запрещен для ГБ-маркета, потому что не поддерживает прямой перевод ГБ.

Отдельный продуктовый риск: общие аккаунты без официальной семейной механики лучше не продвигать как "семью". Для них нужен отдельный тип с предупреждением о приватности и риске блокировки.

- Реализованы основы GB Market, trust score, deal flow и UI доверия.
- После технического сбоя кодовая база была восстановлена, зависимости и Tailwind/HeroUI стабилизированы.

### Март 2026

Работа сместилась к удобству поиска и интерфейса:

- Добавлены вкладки All/My, поиск с debounce и фильтры по категориям.
- Документы и UI-спеки приведены к более аккуратному виду.

### 31 мая - 2 июня 2026

Проект начал превращаться в настоящий Telegram Mini App:

- Переделан UI под мобильное приложение, а не сайт.
- Взято направление на визуальный стиль, близкий к Yandex Pay / Yandex Plus / Yandex Delivery: крупная типографика, светлый фон, плотные карточки, понятные CTA.
- Исправлены safe-area, нижняя навигация и пустые отступы.
- Добавлены категории главной страницы под реальные потоки рынка.
- Убраны лишние поля вроде региона и типов места.
- Доработан GB-маркет: покупка, продажа, сделки, операторские ограничения.
- Переработан экран создания семейной подписки.
- Настроены Telegram-группы: создание/выбор группы, добавление бота, автоподтягивание invite-ссылки.
- Подключен деплой на Vercel.
- Настроен локальный Telegram dev через HTTPS-туннель, чтобы не деплоить каждую мелкую правку.

### 3 июня 2026

Главный сдвиг дня - строгий flow вступления и DDD-правила:

- Заявки перестали автоматически превращать пользователя в активного участника.
- Хост теперь получает заявку и может написать пользователю в Telegram до принятия.
- Ссылки из уведомлений открывают Mini App, а не обычный сайт.
- Добавлены уведомления об успешном принятии/отклонении.
- Реализован новый статусный flow:
  - `pending` - заявка отправлена;
  - `invited` - хост принял, но доступ еще не выдан;
  - `payment_pending` - доступ выдан, запущен 30-минутный таймер;
  - `paid` - участник отметил оплату;
  - `active` - хост подтвердил оплату;
  - `removed`, `rejected`, `disputed` - ошибочные/конфликтные ветки.
- Добавлен DB sweeper внутри FastAPI: просроченная оплата автоматически переводит участника в `removed` и освобождает место.
- Добавлен AuditLog как отдельная системная история действий.
- Добавлена заморозка семьи при споре.
- Backend запрещает Altel в ГБ-маркете независимо от UI.
- Создан доменный слой правил `backend/src/domain/rules/club_state_machine.py`.

## 6. Текущая архитектура

Backend:

- FastAPI.
- SQLAlchemy async.
- PostgreSQL.
- Alembic migrations.
- Telegram WebApp auth.
- Telegram Bot notification service.
- Domain layer с сущностями и отдельным state machine для правил клуба.
- Application layer с `ClubService`, `NotificationService`, `payment_sweeper`.
- Interface layer с API routes и Pydantic schemas.

Frontend:

- React 19.
- TypeScript.
- Vite.
- Tailwind.
- React Router.
- TanStack Query.
- Telegram Mini App integration.

Локальная разработка:

- Backend: `http://localhost:8000`.
- Frontend: `http://localhost:5173`.
- Telegram-тест через HTTPS tunnel.
- Vite proxy прокидывает `/api` на backend, чтобы Mini App на телефоне не ходил в свой `localhost`.

## 7. Что уже реализовано по новой логике

Реализовано:

- Pending-заявки не занимают место.
- `current_members` считает только занятые места, а не всех заявителей.
- Хост видит заявки отдельно.
- В заявке есть кнопка "Написать", если у пользователя есть Telegram username.
- Принятие заявки переводит участника в `invited`, а не `active`.
- Хост вручную нажимает "Доступ выдан".
- После выдачи доступа стартует 30-минутный payment timer.
- Участник видит реквизиты только после выдачи доступа.
- Участник нажимает "Оплатил".
- Хост подтверждает оплату.
- Только после этого участник становится `active`.
- Просрочка оплаты автоматически освобождает место.
- Спор переводит участника в `disputed`, а клуб в `frozen`.
- Frozen блокирует join/approve/issue-access/confirm-payment.
- AuditLog пишет ключевые переходы.
- Altel в ГБ-маркете запрещен на backend-уровне.

Проверено локально:

- Backend компилируется.
- Frontend build проходит.
- API flow заявки, принятия, выдачи доступа, оплаты и подтверждения проходит.
- Frozen flow проходит.
- Sweeper flow проходит.
- Altel offer отклоняется.

## 8. Где есть несостыковки

Старые документы местами устарели:

- `PROJECT_MASTER.md` говорит "Passive Platform" и "No frozen".
- Текущая продуктовая логика уже другая: платформа не хранит деньги, но enforce-ит правила и замораживает спорные семьи.
- `README.md` местами описывает старую структуру и старые категории.
- `PROJECT_MEMORY.md` упоминает Altel в GB Market, хотя теперь Altel должен быть запрещен для передачи ГБ.

Это нужно обновить, иначе новый ИИ/разработчик будет получать противоречивые инструкции.

## 11. Вывод

Текущее направление правильное: SubsMarket должен быть не escrow и не банком, а строгим Telegram Mini App, который снижает хаос рынка через статусы, прозрачность и историю действий.

Самая сильная MVP-идея сейчас: "доступ вперед денег, 30 минут на оплату, все действия зафиксированы". Это прямо закрывает главные боли из Telegram-чата и не требует банковских интеграций.

Главная техническая задача перед деплоем: зафиксировать новую модель в документах и тестах, чтобы старое понимание "пассивной доски" не конфликтовало с новой системой правил.
